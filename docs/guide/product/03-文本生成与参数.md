# 产品篇 03：文字怎样生成，参数怎样控制结果

> 主题：文本生成、参数、停止条件与结果解释。
> 依据：src/main.cpp、src/sampler.cpp/h。
> 示例类型：命令可运行；小数组为原理示例。
> 规范：tech-doc v1.1。

## 1. 生成并不是一次得到整篇回答

程序先读完整段输入，再选择一个新 token，把它接到历史后面，继续计算下一个。新 token 不一定是一个汉字或一个完整单词，所以参数里的“长度”不能直接当成字数。

原理示例：起始文字是“今天”，第一轮选到“天气”，下一轮基于“今天天气”继续选。真实模型如何切分这些文字由词表决定，本例不指定真实 token 编号。

## 2. 能设置哪些参数

| 参数 | 含义 | 实例 |
|---|---|---|
| --model | 模型文件路径，必填 | --model models/example.gguf |
| --prompt | 起始文字，不能为空 | --prompt "Hello" |
| --n | 最多生成多少个新 token，默认 128 | --n 8 |
| --temp | 温度，默认 0.8；小于等于 0 时取最高分 | --temp 0 |
| --top-k | 限定高分候选数量，默认 40 | --top-k 10 |
| --top-p | 根据累计概率限定候选，默认 0.95 | --top-p 0.9 |
| --seed | 随机数种子，默认 1234 | --seed 42 |

温度不是“答案准确度旋钮”。低温使选择更集中，高温使存活候选之间的分布更平；两者都不能代替事实验证。固定种子用于相同实现和环境下复现实验，不承诺跨推理引擎或跨平台逐 token 相同。

## 3. 实例：观察确定性生成

```bash
./build/mini-llama \
  --model models/TinyLlama-1.1B-Chat-v1.0.Q8_0.gguf \
  --prompt "Hi" --n 4 --temp 0
```

输入是 Hi，最多生成 4 个新 token。temp=0 时每轮选择最高分编号；若遇到结束 token，可少于 4 个。这条命令没有在本章重新执行，不预设续写内容。

使用更短生成长度可以减少学习时的等待。对于本项目，模型加载和输入处理仍有开销，--n 变小不意味着总时间同比缩短。

## 4. 实例：理解候选选择

以下为原理示例，不是真实模型词表：

| 候选编号 | 代表文字 | 模型分数 |
|---|---|---|
| 0 | 巴黎 | 3 |
| 1 | 里昂 | 2 |
| 2 | 伦敦 | 1 |

- temp=0：输出编号 0，最高分候选胜出。
- top-k=1：随机路径也只剩编号 0。
- top-k=2：第三个候选被排除，前两个仍需按后续策略选择。

这只说明选词规则，不能证明“巴黎”在当前真实模型中具有上述分数。

## 5. 输入问题与对话模板

本项目接收原始字符串，不会自动插入模型要求的角色标记、系统提示或对话模板。模型是 Chat 版本，并不意味着传入一句裸文本就等于完整聊天请求。

多轮对话也没有内置会话接口。如果调用方把历史对话拼进 prompt，程序会把它作为新的一段输入重新处理；没有跨 CLI 进程复用缓存。

## 6. 停止与异常

正常停止有两种：遇到词表给出的结束 token，或达到 --n 上限。缓存容量不足、输入不兼容等错误会走异常退出，不属于正常结束。

长度参数没有把超长上下文变成无限内存。输入和生成都消耗位置，不能越过模型配置及缓存容量。修改参数后重新运行是新的一次推理，不会接着上次的进度。

## 7. 目前没有的生成控制

没有重复惩罚、语法约束、自动 JSON 校验、工具调用编排、联网检索和内容正确性检查。即使 prompt 写“只输出 JSON”，程序也没有结构化输出保证。
