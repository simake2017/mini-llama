# 产品篇 04：怎样看见推理的内部过程

> 主题：教学工具的入口、输出和检查范围。
> 依据：lines/ 与 tests/test_lines.cpp。
> 示例来源：本次会话的历史运行片段。
> 规范：tech-doc v1.1。

## 1. 业务线工具是什么

普通生成命令侧重最终文字，业务线工具侧重中间过程。一条线是一个可运行的子流程，配有步骤说明、源码入口、观察值和轻量检查。--step 会在每跳等待回车，方便边读边运行。

业务线的示例输入通常写在各自 cpp 中；它们不是通用生成 CLI，不能假定支持 --prompt。

## 2. 八条线分别观察什么

| 族 | 线 | 输入 | 输出或检查 |
|---|---|---|---|
| load | model_load | GGUF 文件 | 模型配置、张量与权重装载 |
| load | vocab_load | GGUF 词表元数据 | 词表类型、索引、特殊 token |
| text | tokenize | 预设文字 | token 编号序列 |
| text | detokenize | token 序列 | 还原后的文字 |
| infer | prefill | 预设 prompt | 打分、缓存和一致性检查 |
| infer | decode | 初始打分和缓存 | 若干轮生成与缓存增长 |
| numeric | dequant | 合成量化块及模型张量 | 还原的浮点数 |
| numeric | sample | 预设分数数组 | 候选过滤与采样检查 |

## 3. 实例：看文字被切成什么

```bash
MINILLAMA_MODEL=models/TinyLlama-1.1B-Chat-v1.0.Q8_0.gguf ./build/mini-llama-lines tokenize --step
```

该线使用 Hello world 2026, 你好！作为示例。历史运行的部分输出：

```text
编码后 token 数 = 15
token[0] id=1 文本="<s>"
token[1] id=15043 文本="▁Hello"
token[2] id=8879 文本="▁wo"
token[3] id=2096 文本="rl"
token[4] id=29881 文本="d"
解码回来 = <s> Hello world 2026, 你好！
```

这是当前文件的观察，不是所有 TinyLlama 词表的通用结果。开头空格和特殊 token 的呈现与词表配置及 token 类型相关。

## 4. 实例：看历史缓存是否写入

```bash
MINILLAMA_MODEL=models/TinyLlama-1.1B-Chat-v1.0.Q8_0.gguf ./build/mini-llama-lines prefill --step
```

该线编码的 prompt 是 Hi。历史输出片段：

```text
第 0 层位置 0 的 K 向量模 = 1.3779
第 0 层位置 0 的 V 向量模 = 0.080459
最大逐元素差 = 0
clear 后复用的最大差 = 0
```

前两项说明缓存存在非零数据，后两项比较两种调用方式和清空后复用的结果。它们是特定输入上的检查，不能单独证明完整推理实现与上游一致。

## 5. 验证入口

```bash
./build/mini-llama-lines --list
ctest --test-dir build --output-on-failure
```

历史 ctest 结果为 7/7 通过，包括 gguf、tokenizer、model、generate、quant、lines、lines_model。该结果属于当时的代码和环境，本轮文档修改没有重新运行推理测试。

有些线不需要真实模型，可以用合成数据运行；需要模型的线应明确设置 MINILLAMA_MODEL。以输出中的检查结果和是否跳过为准，不能把“没运行真实模型”当成“真实模型验证通过”。

## 6. 学习顺序与边界

推荐按 model_load → vocab_load → tokenize → detokenize → prefill → decode 阅读，再单独理解 dequant 和 sample。族文档位于 lines/load、text、infer、numeric 的 README.md。

工具帮助观察本程序，不会自动生成上游对照报告，也不替代调试器。遇到检查失败，先记录输入、模型、具体检查和实际输出；不要只保留最后一行通过或失败统计。
