# 技术篇 03：词表、分词与解码

> 主题：文字与 token 编号的双向转换。
> 依据：Tokenizer::load/encode/decode/merge_tokenize、src/unicode.cpp。
> 上游基准：llama.cpp @ 88b47a755。
> 规范：tech-doc v1.1。

## 1. 为什么先把文字变成整数

网络不能直接对字符串做矩阵计算。词表为每个文字片段分配一个编号，编码器把输入变成编号序列，网络再按编号查出词向量。token 可以是完整单词、单词的一部分、符号或字节，不能等同于汉字或英文单词。

| 数据 | 形状 | 意义 |
|---|---|---|
| 输入文字 | 字符串 | 用户提供的文本 |
| 词表 | 编号到片段、片段到编号的索引 | 定义编号含义 |
| 编码结果 | vector<int> | 交给网络的 token 编号 |
| 解码结果 | 字符串 | 拼接还原的文字 |

## 2. 两条编码路径

本实现包含 SPM 与 BPE 路径。前者涉及空格前缀、▁ 转义及按词表 score 合并；BPE 路径涉及预分词和按配置执行的字节映射。它们复用部分相邻片段合并实现，但预处理并不相同。

总体流程为：读取词表配置 → 预处理文本 → 初始化符号 → 将能合并的相邻片段入队 → 按优先级合并 → 输出编号或进入兜底分支 → 按参数添加特殊 token。

这里没有完整的 Unicode 归一化系统，不能把转义和预分词描述成实现了 NFKC 等所有规范化能力。

## 3. 历史实例：不是一个单词一个编号

输入 Hello world 2026, 你好！，使用当前模型时的历史输出前缀：

```text
[1, 15043, 8879, 2096, 29881, ...]
对应 ["<s>", "▁Hello", "▁wo", "rl", "d", ...]
```

解码得到：

```text
<s> Hello world 2026, 你好！
```

这说明 world 在该次输入中被分成多个片段，编号由该文件的词表决定。仅能成功往返不能证明编码编号与上游完全相同；对齐测试必须比较两端的编号序列。

## 4. 解码过程

编号 → 取词表片段 → 按类型处理特殊 token 或字节 → 逆转义空格、还原字节映射 → 拼接字符串。

特殊 token 不一定全部消失。当前文件的一些标记是 USER_DEFINED 类型，可能按文本原样呈现。遇到输出中的占位标记，应先查看实际词表和 token 类型，不能一律认定为打印工具加入。

## 5. 错误和已知边界

词表元数据缺失或类型错误会导致加载失败。字节兜底用于覆盖词表未直接表示的片段，但当前实现存在边界：SPM 未命中的多字节字符和查找失败可能丢失内容。因此不能宣称任意输入绝对无损。

另有 add_bos 与上游 add_bos_token 键名差异，已登记在单元文档中。本章只解释当前实现，不把这些偏离视为已修复。
