# 技术篇 01：整体架构与一次推理

> 主题：从文件和输入文字到生成文字的完整执行链。
> 依据：src/main.cpp、PROJECT.md。
> 参考实现：llama.cpp @ 88b47a755；还原规范 mini-restore v1.2。
> 文档规范：tech-doc v1.1；本文为现有实现导读。

## 1. 概念与模块

| 模块 | 负责什么 | 核心对象 |
|---|---|---|
| gguf | 文件解析、元数据、张量字节访问 | GgufFile、TensorInfo |
| tokenizer、unicode | 词表装载、文本编码与解码 | Tokenizer |
| model | 超参、权重组织、网络前向 | HParams、Model |
| kvcache | 保存各层各位置的历史 K/V | KVCache |
| sampler | 从打分选择编号 | Sampler、SamplerParams |
| quant | 解释受支持的低精度权重 | dequant_row_* |
| main | 命令行参数和生成编排 | CLI |

词表决定编号含义，模型权重决定如何计算，采样器决定如何从候选中选择。三者共同影响结果。

## 2. 正常流程

```text
GGUF 文件 → 解析元数据与张量 → 装载词表和网络权重
                                      ↓
输入文字 → token 编号 → 逐位置处理输入 → 末位打分
                                      ↓
                 选择新 token → 解码输出 → 增量前向
                      ↑                       │
                      └──── 下一轮打分 ───────┘
```

每次选择后先检查结束 token；如果不是结束 token，就输出文字并执行新 token 的前向。达到生成上限后结束循环。文件加载与文本生成不是两个独立进程。

## 3. 实例：输入经过哪些形状

原理示例，编号与维度均为便于理解而缩小：

| 阶段 | 输入 | 输出 |
|---|---|---|
| 编码 | Hello | [1, 7] |
| 预填充 | [1, 7] | 缓存有两个历史位置，末位分数长度为词表大小 |
| 采样 | [0.1, 0.8, -0.2] | 编号 1（若使用贪心） |
| 增量前向 | 新编号 1 与已有缓存 | 第三个位置的新分数 |

真实 TinyLlama 示例的隐藏维度为 2048，词表为 32000；一个位置最终输出长度为 32000 的打分向量，不是直接输出一个英文单词。

## 4. 持久状态与修改

GGUF 文件只读。词表、权重组织、临时向量与缓存均存在进程内。缓存的逻辑变化可用以下原理示例表达：

```jsonc
// 处理下一个 token 前
{"processed_positions": 2}
// 处理完成后；不是写回模型文件
{"processed_positions": 3}
```

模型映射必须覆盖使用权重的生命周期。每次启动 CLI 都重新建立运行状态。

## 5. 异常与范围

文件不可读、张量不兼容、缓存容量不足等错误由核心 API 抛出后，CLI 捕获、打印并返回 1。参数不完整返回 2。修改输入或文件后可重试；同一不支持架构原样重试无效。

没有计算图调度器、GPU 后端或多序列服务。这些是本项目明确裁剪的范围，不能据此推断完整 llama.cpp 的结构。
