# 技术篇 04：Transformer 前向计算

> 主题：模型如何把一个 token 和它前面的上下文变成下一步的分数。
> 依据：Model::forward_token、src/model.cpp。
> 上游基准：llama.cpp @ 88b47a755；规范：tech-doc v1.1。

## 1. 输入和输出

前向计算一次处理一个 token 位置，并接收该位置之前已经写入的 KV 缓存。输入 token 编号先查 embedding 矩阵，取出长度为隐藏维度的向量；经过多个 Transformer 层后，输出头把最终向量映射为词表中每个 token 的分数 logits。

当前 TinyLlama 示例中隐藏维度是 2048、词表大小是 32000，因此输出分数有 32000 个。分数不是概率，也不是生成文字；采样器还要据此选择一个编号，Tokenizer 才能把编号解码成文本。

## 2. 一层里发生什么

本项目的 LLaMA 风格层按以下主干运行：

```text
输入向量
  → RMSNorm
  → Q、K、V 投影
  → RoPE 位置旋转
  → 写入 K/V 缓存
  → 查询与历史 K 做注意力
  → 权重加权历史 V
  → 输出投影并残差相加
  → RMSNorm
  → SwiGLU 前馈网络
  → 输出投影并残差相加
```

RMSNorm 按向量均方根尺度归一化并乘可学习权重。Q 表示当前位置要查询什么，K 表示各位置可被匹配的特征，V 是匹配后用于汇总的信息。RoPE 将位置信息编码进 Q、K。因果注意力只允许当前位置读取当前及之前的位置。

SwiGLU 是带门控的前馈变换：两条投影分支经激活与逐元素相乘，再投影回隐藏维度。残差连接把子层输入加回输出，避免每层都丢掉原有表示。

## 3. GQA 与注意力形状

查询头数可以多于 K/V 头数；多个查询头共享一组 K/V 头，这就是分组查询注意力 GQA。当前历史模型有 32 个查询头、4 个 K/V 头。K/V 缓存只保存 K/V 头对应的数据，不是为每个查询头重复存一份。

简化原理例：假设有 4 个查询头和 2 个 K/V 头，则每两个查询头共享一组 K/V。实际映射和张量形状由模型超参数决定，不能只凭模型名称推算。

## 4. 小数字例：分数如何产生

以下仅用于理解矩阵运算，不是本模型输出：

| 步骤 | 输入 | 输出 |
|---|---|---|
| embedding | token id 7 | 隐藏向量 [1, 0] |
| 简化前向 | [1, 0] 与历史上下文 | 最终向量 [0.2, 0.8] |
| 简化输出头 | 最终向量 | logits [0.1, 1.2, -0.3] |

logits 中编号 1 的分数最高，但程序仍需经过采样规则；它对应什么文字要由同一模型文件的词表决定。不能把向量的第 1 项直接解释为某个固定单词。

## 5. 输入位置与缓存

prefill 对输入 token 逐位置调用前向，每个位置都能读取它之前的缓存；decode 则只计算新生成的那个位置。注意力分数会经 softmax 转成权重，再对历史 V 加权汇总。细节和缓存布局见下一章。

## 6. 错误与实现边界

必要权重缺失、形状不符或权重类型不受支持时，前向不能得到有效分数，应报错退出。当前实现服务于约定的 LLaMA 风格模型，不是任意 GGUF 架构的通用执行器；解析器能读出张量不代表前向知道其语义。
