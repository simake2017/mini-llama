# 技术篇 06：采样与生成控制

> 主题：模型给出一组分数后，程序怎样选择下一个 token。
> 依据：Sampler::sample、SamplerParams、src/sampler.cpp。
> 上游基准：llama.cpp @ 88b47a755；规范：tech-doc v1.1。

## 1. logits 不是答案

前向计算为词表中的每个 token 给出一个 logits。它是相对分数，不是概率；采样器先筛选候选，再把存活分数变成概率，最后选择一个 token。被选 token 交给 Tokenizer 解码，并进入下一轮前向。

## 2. 当前实现的精确顺序

当前实现的顺序是：

```text
原始 logits
  → softmax 得到原始概率并排序
  → top-k 截断
  → 按累计概率执行 top-p 截断
  → 对存活候选的 logits 应用 temperature
  → 再次 softmax
  → 按概率随机抽样
```

top-k 先限制数量，top-p 再限制累计概率。top-p 会保留使累计概率跨过阈值的那个候选。温度作用在已经存活的候选上，因此不能用“先调温度再 top-p”解释当前代码。

## 3. 原理实例：分数 3、2、1、0、-1

下面是采样线使用的简化分数，编号仅代表候选位置：

```text
logits = [3, 2, 1, 0, -1]
```

softmax 后概率从高到低排列。以 top-p=0.9 为例，当前实现保留编号 0、1、2；编号 3 和 4 被排除。即使之后把 temperature 调高，已被 top-p 排除的编号也不会重新出现。

当 temperature=0 或小于 0 时，代码直接选择最高分编号 0，不走随机抽样。temperature=2 时，存活候选之间的概率更平，但仍只从存活集合中选择。

这是规则示例，不是模型对任何真实词语的分数，也不表示编号 0 对应固定文字。

## 4. 参数如何影响结果

| 参数 | 作用 | 边界 |
|---|---|---|
| temperature | 改变存活候选之间的分布尖锐程度 | 小于等于 0 变成 argmax |
| top-k | 保留排序靠前的候选数量 | 不能让低排名候选进入 |
| top-p | 保留累计概率覆盖阈值的候选 | 不能让已排除候选复活 |
| seed | 初始化随机数发生器 | 只保证相同实现和环境下便于复现 |

低温通常更集中，高温通常更分散，但它们不检查事实、不修正模型知识，也不能保证输出语法正确。固定 seed 不承诺跨引擎、跨平台或不同浮点实现逐 token 相同。

## 5. 停止条件

CLI 每轮先检查采样出的 token 是否等于词表的 EOS 编号。是则立即停止且不打印 EOS；否则先解码输出，再将该 token 做增量前向。达到 `--n` 上限也会停止。没有重复惩罚、语法约束、JSON 校验或工具调用编排。

## 6. 异常与观察方式

调用方必须保证 logits 缓冲区覆盖传入的长度。Sampler 在长度小于等于 0 时抛出“sample: 空 logits”；它不执行完整的参数和缓冲区合法性验证。top-k 小于等于 0 表示不限制数量；top-p 只在 0 与 1 之间启用截断，其余值不启用。CLI 捕获标准异常并返回错误码 1，缺少必需的 `--model` 或 `--prompt` 返回错误码 2。

建议先用 `--temp 0 --n 4` 做确定性观察，再逐步打开 top-k、top-p 和温度。确定性只帮助定位流程，不代表结果质量。实际生成输出应同时记录模型文件、prompt、参数和 seed。
