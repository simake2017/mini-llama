## 1. 四段式（顺序固定，不许换、不许省）

| 段 | 内容 | 本项目的行数预算 |
|---|---|---|
| ① 定位 | 一句话说清「这是什么、干什么」 | 1~2 行 |
| ② 源码锚点 | 对应**上游实现**的确切 `文件:行:函数` | 2~4 行 |
| ③ 动机 | **为什么必须这样设计**（不是复述代码） | 2~5 行 |
| ④ demo + 多方样例 | 终态多组样例 + 交叉印证视角 | 6~15 行 |

整块 **≤ 25 行**（复杂算法 30、多步协议 40 且须说明理由）。
超了 = 有推演没删干净。

### C++ 落地形态

```cpp
// ============================================================================
// ① 定位：RoPE 旋转位置编码——把「位置」编码进 query/key 的维度里
//
// ② 源码锚点：
//    llama.cpp @ 88b47a755  src/llama-model.cpp:LLM_ARCH_LLAMA 的 rope 类型分派
//                          → LLAMA_ROPE_TYPE_NORM（"operating on pairs of
//                            consecutive head values"）
//    llama.cpp @ 88b47a755  ggml/src/ggml-cpu/ : ggml_rope_ext 的 neox=false 分支
//
// ③ 动机：
//    【陷阱】llama.cpp 当前版本对 LLaMA 系走的是「相邻配对」(2i, 2i+1)，
//    不是老教程里的「前半后半配对」(half-split / NEOX)。两者数学上不等价——
//    要互换得在加载期对 wq/wk 做行置换。与上游逐数值对拍必须用同一约定，
//    否则 logits 在多位置混合序列上分叉。
//
// ④ demo + 多方样例：
//    🟢 pos=0：任意配对约定都是恒等变换（所以 pos=0 的单 token 测试测不出错）
//    🟡 pos=1, h=4, theta=10000：x=[1,0,0,0] → [cos θ0, sin θ0, 0, 0]
//       其中 θ0 = 1 * theta^0 = 1
//    🔴 上游对照：llama.cpp @ 88b47a755 同输入下 logits max|Δ| ≤ 0.27
//       （FP32 累加顺序噪声量级，见 docs/05-quantization.md 验收记录）
//    调用方：src/model.cpp 的 forward_token 逐头调用本函数
// ============================================================================
```

## 2. 分层落点（**按重要性分层，不要求逐个符号写满**）

| 对象 | 写什么 | 本项目的具体清单 |
|---|---|---|
| **文件头** | 四段式（必写） | `src/*.h`、`src/*.cpp` 全部 16 个文件；`lines/_shared/line.hpp` 等新增文件同样适用 |
| **承重类型 / 导出的主入口** | 四段式（必写），③ 尤其不能只写「关键区别」 | 类型：`GgufFile` / `GgufValue` / `TensorInfo` / `HParams` / `TensorBuf` / `LayerWeights` / `Model` / `Tokenizer` / `KVCache` / `Sampler` / `SamplerParams` / `TokenType`<br>主入口：`GgufFile::load` / `Tokenizer::load` / `Tokenizer::encode` / `Tokenizer::decode` / `Model::load` / `Model::forward` / `Model::forward_token` / `KVCache::append` / `Sampler::sample` / `dequant_row_*` 四件套 |
| **反直觉的地方**（顺序反直觉、约束隐晦） | 四段式 | ① RoPE 相邻配对约定<br>② KV 追加协议下「本位置已写入」≠「全局 size」<br>③ GGUF 数据区的**双重对齐**（数据区起点绝对对齐 + 张量间各自相对对齐）<br>④ K-quants 的 6bit scale 双路解包（j<4 / j>=4）<br>⑤ SPM 句首补空格与 `add_special` 无关 |
| **私有辅助函数 / 辅助类型** | 2~3 行「为什么这么做」即可，**不写四段式** | `Cursor::read_le` / `read_value` / `find_by_text` / `byte_token` / `merge_tokenize` 的内部辅助 / `load_tensor_f32` 等 |

**为什么分层**：注释密度该由重要性决定，不该均质。均质写满 = 注释量翻几倍，
真正该讲的地方被淹没。

**三层内容不重复**：文件头讲「这个文件整体是什么」，类型讲「这个结构为什么长这样」，
函数讲「这个行为为什么这样表现」。

## 3. 禁止清单

| 禁止 | 为什么 | 改成 |
|---|---|---|
| **复述代码** | `allocated_.set(idx); // 标记为已分配` | 删掉，或写「为什么需要这个标记」 |
| **逐步推演** | `order=0：伙伴 1^1=0 在链上 → 摘除 → current={0}` | 删掉；读者能跑代码验证 |
| **罗列穷举** | `PFN 6→7、PFN 4→6、PFN 0→4` | 留「终态」那张图或表 |
| **废话形容** | "这是最经典的算法之一" | 删掉 |
| **未实测的断言** | "真机上应该是 xxx" | 实测过再写，或不写 |
| **私人笔记** | `// wangyang 从某页开始...` | 删掉 |

**本项目已知的存量问题**（迁移时顺手修掉）：

| 位置 | 问题 | 修法 |
|---|---|---|
| `src/model.h` 的 `rope_rotate` 注释 | 写的是「half-split（两半对旋）风格」，与 `src/model.cpp:rope_rotate` 的**相邻配对**实现相反，且【历史】段说反了 | 改成与实现一致，并标【陷阱】；依据见 `docs/03-forward.md` §17.3 |

## 4. 教学标签（③ 动机段的写法变体）

标签**不是新结构**，它是 ③ 段的写法变体——标签开头，后面紧跟「为什么」。
取值固定六个：`【概念】` `【陷阱】` `【对照】` `【简化】` `【历史】` `【性能】`。

| 标签 | 什么时候用 | 本项目范例 |
|---|---|---|
| `【概念】` | 讲原理 / 设计模式 | `src/kvcache.h`：「为什么 KV cache 是推理的命门——没有缓存每步重算历史是 O(t²)，有缓存是 O(t)」 |
| `【陷阱】` | 容易踩的坑 | `src/model.cpp:rope_rotate`：「llama.cpp 当前版本用相邻配对，不是 half-split」 |
| `【对照】` | 与上游的差异 | `src/quant.h`：「K-quants 的块布局对照 ggml-quants.c 的 block_q4_K」 |
| `【简化】` | 为什么可以砍 | `src/gguf.h`：「不做哈希索引——元数据只有几十条，线性查找纳秒级」 |
| `【历史】` | 演进原因 | `src/tokenizer.cpp`：「SPM 的句首空格是历史规范，llama.cpp 至今保留」 |
| `【性能】` | 性能相关决策 | `src/model.cpp`：「matvec 用三层循环而非分块，因为教学版不追求吞吐」 |

**`【简化】` 必须能答出承重判据**——写「因为简单」不算理由，要写「砍掉它，
哪个核心概念塌了？为什么没塌」。答案查 `04-对齐约束.md`。
判不出来的 = 承重件，不许用【简化】标签一笔带过。

## 5. 3 档用例

**3 档只给「包的公共主入口」**，不是每个导出函数都来一遍。

| 位置 | 档数 |
|---|---|
| 包的公共主入口（用户 90% 会调的那个 API） | **3 档**（🟢🟡🔴） |
| 辅助 API（内部常用、语义简单） | 1 档（🟡 典型）即可 |
| 类型级示例（怎么构造这个类型） | 放**文件头**，不逐类型重复 |

本项目的公共主入口清单（**必须**给 3 档）：

| 主入口 | 🟢 最小 | 🟡 典型 | 🔴 极限 |
|---|---|---|---|
| `Model::forward` / `Model::forward_token` | 单 token，pos=0 | 一段 prompt 顺序推进 | 塞满 `n_ctx` 的长序列 |
| `Tokenizer::encode` | 英文短词 | 中英混合 + 标点 | 大量未登录字符（走 BYTE 兜底） |
| `Sampler::sample` | `temp=0` 纯贪心 | `temp=0.8 + top_k=40 + top_p=0.95` | 高温 + 大 top-p（开放生成） |
| `GgufFile::load` | 合成小文件 | 真实 Q8_0 模型 | 真实混合量化模型（Q4_K_M） |

已有的范例：`src/sampler.h` 的 `SamplerParams` 已是三档写法（🟢/🟡/🔴 三行注释），
其余按上表补齐。

## 6. 日志分级

**本项目的日志默认不打**——教学项目跑起来会刷屏，反而不利于观察主流程。

| 级别 | 用在哪 | 本项目范例 |
|---|---|---|
| 0 Info | 关键生命周期事件（模型加载完成、生成结束） | `std::cerr << "模型: ... 层数= ... 词表= ..."` |
| 1 摘要 | 一轮循环的结果摘要 | `"prefill 完成: N tokens"` / `"生成 N tokens，耗时 Xs（Y tok/s）"` |
| 2 决策理由 | **为什么**选这条路（分支、拒绝、拒绝理由） | 采样器里「temp<=0 → 退化为贪心」这类分支 |
| 3 原始事件 | 收到的数据原样 | 单元 5 的量化类型分支（选了哪条 dequant） |
| 4+ 调试细节 | 单步追踪、字段级 dump（默认关） | 权重加载的逐张量 dump |

硬要求：

- 级别 2 只在**分支决策**处打，不要变成语句流水账
- 级别 4+ 默认关闭
- 本项目的日志走 `std::cerr`，不引 klog（见 §8 的替换登记）

## 7. 【教学】标记与教学便利代码的位置

参考实现**没有**、本项目自己加的代码，必须让人一眼知道它不属于还原范围。

三条硬要求：

1. 集中在**入口外壳 / 测试 / 工具**目录，**核心库不许 import 它**
   （本项目：`src/main.cpp`、`tests/`、`tools/`；核心库 = `src/` 里的
   `gguf` / `tokenizer` / `unicode` / `model` / `kvcache` / `sampler` / `quant`）
2. 【教学】标签**按文件标一次**——文件头写一行「本文件含教学便利代码，
   见 §16.4 第 N 项」，文件内的教学函数不再逐个贴标签
   （标签密集反而让人分不清重点）；例外：教学代码混进了核心路径，
   那就在那个函数上单独标一次并说明原因
3. 进技术文档 **§16.4** 登记（参考实现没有 → 明确列出「我多了什么」）

**本项目的例外登记**：`src/main.cpp` 是 CLI 入口，形态上对应上游 `examples/cli`，
**不算自创**，但它确实不在上游的库本体里——所以在文件头标【教学】并指向 §16.4。
