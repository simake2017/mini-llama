## 1. 承重判据：某个功能能不能砍

「功能最小还原」**不能按功能清单砍**。参考实现的很多模块是**承重件**——
它不在业务功能列表上（它是存储实现、是基础设施、是并发原语），
但砍掉它不是「少一个功能」，是**核心概念直接不成立**。

### 判据一句话

> 砍掉 X 之后，Y 这个核心概念的语义还成立吗？
>
> - **成立** → X 是边缘加固，可以砍
> - **不成立** → X 是承重件。砍了就得换概念 → 那不是「最小还原」，是「另一个东西」

### 三个测试

| 测试 | 问什么 | 不通过 = |
|---|---|---|
| **概念测试** | 砍掉 X，Y 对外承诺的语义还成立吗？ | Y 必须改定义 → X 承重 |
| **行为测试** | 砍掉 X，Y 的**典型**使用路径还能跑通吗？（不是全部路径，是典型路径） | 跑不通 → X 承重 |
| **术语测试** | 砍掉 X，真实世界的用户还会用 Y 这个名字吗？用的话，含义变了吗？ | 名字还在但含义变了 → X 承重 |

### 判的粒度分两档

| 档 | 判定方式 | 记录粒度 |
|---|---|---|
| **明显边缘加固**（一眼看出：动了不影响概念 / 行为 / 术语） | 归成一类**批量判** | 每类写**一条代表性结论** + 列出被归入这一类的条目清单 |
| **看着像承重件** | **逐条三测**，一个都不许省 | 每条一行，三个测试各给结论 |

**批量判的前提**：这一类的条目**同一种形状**。形状不同就不能并成一批——
比如「换个容器」可以批量，「少一个字段」必须逐条三测（字段本身就是结构档的事）。

**不许写「不确定」。** 判不出的 = 停下来问人。

### 判不出来的信号（倾向承重，往保守一边站）

- 这个模块在参考实现的架构图上处于「被很多模块依赖」的位置
- 它在参考实现的目录结构里是**顶层包**
- 参考实现的文档把它描述成「核心机制」而不是「优化」
- **砍掉它之后，你的最小版里出现了参考实现没有的替代物**
  （新概念 / 新错误码 / 新状态 / 新目录）← **最强的信号**

### 2.2 逐条三测（看着像承重件，3 条）

这 3 条**不许合批**，三测逐条给结论。

| # | 砍掉什么 | 真实版怎么做 | 概念测试 | 行为测试 | 术语测试 | 结论 |
|---|---|---|---|---|---|---|
| 1 | **GGML 计算图抽象**（先建图、后执行、可复用） | `llama-graph.cpp` + ggml 的 `ggml_graph` / `ggml_backend_sched` | 通过 —— 前向的数学与阶段划分不受影响，「一次前向 = 一次 token 进、一次 logits 出」仍在 | 通过 —— 典型路径（单 token 前向）跑通 | 通过 —— 用户不会因为「没有图」而改叫前向计算 | **承重但复杂 → 降级还原**：换成「阶段顺序固定的直接循环」。丢掉的是「图可复用 / 可并行调度 / 可切后端」三个工程属性，核心概念完整。**接得上**：以后加一层只需要在阶段列表里插一项 |
| 2 | **KV cache 的 slot / cell 复用与 seq_id** | `llama_kv_cache::find_slot`（在 cell 池里挑一个可复用位置） | **不通过** —— `find_slot` 的存在意义是「在多序列 / 乱序到达时决定 K/V 落在哪个 cell」。砍掉它之后 **cell 这个概念塌了**：本实现里 K/V 的位置就是 `pos`，没有独立于位置的 cell 身份 | 通过 —— 单序列顺序生成的典型路径跑通 | 通过 —— 用户仍叫它 KV cache | **承重，不可砍 → 降级还原**：降级为「纯顺序追加（pos == size）」的单序列缓存。「缓存 = 按位置存放的历史 K/V」核心语义完整保留，丢掉的是多序列与乱序到达。**已登记为已知简化**，不允许在后续单元里悄悄把它说成「等价」 |
| 3 | **RoPE 配对约定**（相邻配对 vs half-split） | `llama-model.cpp`：`LLM_ARCH_LLAMA → LLAMA_ROPE_TYPE_NORM`（"operating on pairs of consecutive head values"） | **不通过** —— 两种约定数学上不等价，除非加载期对 wq/wk 做相应行置换 | **不通过** —— 「混合 token 的多位置」序列上两种约定给出不同 logits | 通过 —— 业界统称 RoPE | **承重，不可砍**：必须采用与上游当前版本一致的**相邻配对 (2i, 2i+1)**。这是与 llama.cpp 逐数值对拍的前提；单 token 与同 token 重复序列测不出差别（见 17.3） |

| 分类 | 条数 | 条目 |

| # | 结构档条目 | 本项目的守则 |

### 3.2 实现档（可替换，判据：能力不减 + 以后接得上）

| 参考实现用什么 | 最小版用什么 | 能力是否等价 |
|---|---|---|

## 5. 判不出来的处理

判不出承重结论的（写不出三测结论）→ **停下来问人**，两个出路：

1. **降级还原**：换更简单的机制实现**同一个概念**
2. **扩大 Must Have**：这个能力本来就在最小版范围内，是砍错了

**不许写「不确定」蒙混过去。**
